## [0.2.0] - 2026-08-14

### Added

- `bus.prependListener(event, listener, options?)` and `bus.prependOnceListener(event, listener, options?)` — subscribe at the front of the listener order (Node parity)
- `bus.rawListeners(event)` — returns registered listener functions in registration order (once listeners returned unwrapped, unlike Node)
- `newListener` / `removeListener` meta events with built-in definitions `newListenerEvent` / `removeListenerEvent` — `newListener` fires before a listener is registered, `removeListener` after it is removed, including `once` auto-removal and `removeAllListeners` (reverse order; the removed listener is never notified of its own removal). Meta events follow `emit` semantics (snapshot, `once` auto-removal, errors → `onError`) but do not run middleware

### Changed

- **Breaking**: removed four public helpers that duplicated the type system — `executeListenerSafely`, `executeAsyncListenerSafely`, `EventDefinitionInput`, `EventNamespaceInput`. Errors from listeners now always flow through `onError`/`MultiError`
- `emit` / `emitAsync` now snapshot listeners at emission start (Node semantics): listeners registered during an emit are not invoked in the current emit, and listeners removed during an emit are still invoked in the current emit
- `once` listeners unsubscribe before execution; re-entrant emits no longer re-invoke them
- middleware errors abort the chain and surface via `onError`/`MultiError` instead of being silently ignored
- `next()` called after a middleware has settled (e.g. via `setTimeout`) runs in a late segment; errors in late segments are suppressed instead of surfacing as unhandled rejections
- `Middleware.next` is now typed as `() => Promise<void>` (was `() => void | Promise<void>`)
- `isEventNamespace` narrows to a namespace-shaped object (string `__prefix` + brand) instead of claiming every property is an `EventDefinition`
- `bus.off(event, listener)` now removes the most recently registered instance of a duplicated listener (Node `lastIndexOf` semantics, was first-registered)

### Fixed

- `once` auto-removal now removes exactly the once registration — no longer routes through `bus.off` (lastIndexOf semantics) and removes a separate persistent `on` registration of the same listener function
- `once` auto-removal now deletes from the map's current listener set, so a `prependListener` called during an emit (which swaps the set) can no longer leave the once listener registered, firing repeatedly and leaking a listener per emit
- listeners re-registered to an event while its `removeListener` meta events fire during `removeAllListeners` are preserved (previously dropped with the detached listener set)
- `once` subscriptions removed by auto-removal or `removeAllListeners` now detach their AbortSignal listener and report `unsubscribed === true`
